# SOTA Engineering: The Brain & Muscle Boundary

## 1. The Separation of Concerns
To maintain SOTA performance without losing startup agility, we enforce a strict boundary between the **Brain (Python Orchestrator)** and the **Muscle (Rust Execution)**.

---

## 2. Python (The Brain) Responsibilities
- **DAG Context**: Knowing that Node A flows to Node B.
- **AI Personalization**: Calling LLMs to render a specific message for a specific lead.
- **Campaign Logic**: Handling complex branching (e.g., Thompson sampling, sentiment analysis).
- **Control Plane**: Managing the `Campaign` and `Lead` objects in Postgres.

**Interface**: Emits a `CommandTask` JSON packet to the `outreach.commands` topic.

---

## 3. Rust (The Muscle) Responsibilities
- **Network I/O**: Making the actual HTTPS/SMTP/WebSocket calls.
- **Proxy Tunneling**: Ensuring every request is routed through the correct residential proxy.
- **Rate Limiting**: Throttling requests to stay under LinkedIn/Email provider limits.
- **Error Mapping**: Translating obscure network errors into actionable `ExecutionResult` packets.

**Interface**: Consumes from `outreach.commands` and emits to `outreach.results`.

---

## 4. Why this Boundary is Critical
- **Debugging**: If a message fails to send, we know instantly if it was a **Brain Failure** (bad content generated by Python) or a **Muscle Failure** (proxy timed out in Rust).
- **Iteration**: We can upgrade the AI logic in Python 10 times a day without touching the high-stakes Rust execution code.
- **Safety**: The Rust layer acts as a "Guardian," ensuring that even if the Python code goes haywire and tries to send 1 million messages in a minute, the Rust rate-limiters will block it.
