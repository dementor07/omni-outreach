# ADR 0001 — Omni v2 Nuke: single execution path, pluggable nodes

**Date:** 2026-05-26
**Status:** Accepted
**Deciders:** navij

## Context

The codebase carries two execution paths in parallel — the legacy Python
`dispatcher.py` queue loop and the SOTA Rust/Flink/Kafka grid — gated by
`CHANNEL_MUSCLE_MODE`. Only `email` and `linkedin_invite` are cut over;
every other channel still runs through the legacy path. The result is
~25 routers, ~15 services, ~2,500 lines of mode-switching glue, and
documentation debt that makes the repo unreadable.

The SOTA architecture has been in place for weeks and is the design we
believe in:

  - Event-streaming substrate (Kafka via Redpanda)
  - Stateful keyed orchestration (Flink, keyed by `lead_id`)
  - Rust muscle executes every channel
  - Postgres RLS enforces multi-tenancy at the database layer
  - Credential refs flow through the bus; secrets never travel in payloads

The legacy path is not "an alternative we sometimes use." It is dead
weight blocking the platform's clarity.

## Decision

Discard the legacy execution path in its entirety. Rebuild the control
plane around six small files plus a pluggable node registry.

This is **branch-and-build-fresh**, not in-place. Master keeps running
on the existing code. A `v2-nuke` branch is created from current master,
the legacy code is deleted there, and v2 is deployed to a separate URL
until parity is reached. Master is then reset to v2.

## Architecture

### Keep (the SOTA spine, unchanged)

  - `backend-rust/` — the muscle; every channel handler
  - `backend-flink/` — the orchestrator; keyed state, timers, races
  - `backend/alembic/versions/` — the Postgres schema, migrations 001-020
    (RLS migration 020 is the multi-tenant security boundary)
  - `backend/app/db.py` — asyncpg pool with per-request `app.workspace_id`
  - `backend/app/auth.py` — JWT + workspace context
  - `backend/app/config.py` — env-driven settings (no `changeme` defaults)
  - `backend/app/services/encryption.py` — Fernet at-rest encryption
  - `backend/app/services/workspaces.py` — workspace lifecycle helpers
  - `backend/app/routers/auth.py`, `auth_google.py`, `workspaces.py`,
    `internal.py` — auth + tenancy + muscle-facing endpoints
  - `frontend/` — the React/Vite SPA, canvas runtime kept, pages rebuilt

### Delete (the bloat)

Legacy execution path:

  - `backend/app/services/dispatcher.py`
  - `backend/app/services/command_resolver.py`
  - `backend/app/services/bus.py`
  - `backend/app/services/sequencer.py`
  - `backend/app/services/agent.py`, `agent_tools.py`
  - `backend/app/services/email.py`
  - `backend/app/services/reply_classifier.py`
  - `backend/app/services/optimization.py`
  - `backend/app/services/lead_gen.py`, `lead_sources/`
  - `backend/app/services/job_search.py`
  - `backend/app/services/notifier.py`
  - `backend/app/worker/stream_processor.py`, `tasks.py`
  - `backend/app/services/stream_sync.py`
  - `backend/app/services/transition_worker.py`

Legacy routers (replaced by event log + node registry):

  - `routers/campaigns.py`, `leads.py`, `sequences.py`, `templates.py`,
    `accounts.py`, `queue.py`, `lead_gen.py`, `template_library.py`,
    `tracking.py`, `fragments.py`, `overview.py`, `approvals.py`,
    `blacklist.py`, `analytics.py`, `notifications.py`, `job_search.py`,
    `inbox.py`, `agents.py`, `activity.py`, `settings.py`, `webhooks.py`

Environment variables retired:

  - `EVENT_BUS_MODE`, `EXECUTION_MODE`, `CHANNEL_MUSCLE_MODE`

### Build (six small files + a node registry)

  1. `routers/events.py` — append-only event log API. `POST /events`,
     `GET /events`. Everything else is a projection of this log.
  2. `routers/projections.py` — read-only SQL views: contacts, companies,
     deals, leads, activity timeline. Each view is one query.
  3. `routers/nodes.py` — the pluggable node registry. `GET /nodes` lists
     manifests; `POST /nodes/{type}/execute` runs one. Dispatch by node
     type to a module under `app/nodes/`.
  4. `routers/canvas.py` — DAG CRUD: workflows + nodes + edges. Replaces
     `campaigns` and `sequences`.
  5. `routers/inbox.py` — unified inbox; projection of inbound message
     events.
  6. `routers/integrations.py` — connections CRUD + OAuth flow. Replaces
     `accounts`, `oauth`, `oauth_producthunt` — one generic OAuth handler
     driven by a provider manifest.

### The node registry

```
backend/app/nodes/
  __init__.py            registry, dispatch, manifest validation
  sources/               csv, apollo, hunter, proxycurl, sheets,
                         producthunt, webhook_in
  ai/                    enrich, compose, classify, score
                         (Claude, Gemini, MindStudio behind one interface)
  channels/              email, linkedin, sms, voice, webhook_out, slack
                         (Python is a thin shim; real send is Rust muscle)
  conditions/            field_match, score_threshold, replied
  flow/                  delay, wait_until, race, human_approval
  crm/                   create_contact, update_deal, create_task
```

Each node module is ~50 lines:

  - `manifest`: inputs, config schema (Zod-ish via Pydantic), outputs,
    capabilities, side-effect class
  - `execute(ctx) -> result`: pure function, emits a result event

Adding a new integration (ZenRows, Clay, RB2B, anything) is a single
file in the appropriate category + a register call. No routers change,
no schema migrations, no architectural decisions.

## Consequences

### Lost on day one

The instant the v2 deploy goes live and master is reset, anything that
relied on the legacy path stops working until its node port lands.
Specifically:

  - LinkedIn DM / profile-view / InMail
  - WhatsApp, Instagram, Telegram
  - SMS (Twilio)
  - Voice (Retell)
  - Hot-lead alerts
  - Lead-gen pulls + CSV import
  - AI compose, AI screen, reply classification
  - Outbound webhooks

The Rust muscle already has handlers for most of these channels. The
Python services being deleted were the legacy parallel path, not the
Rust integrations. The bulk of "porting" is wiring the new Python node
manifests to the existing Rust handlers via the same Kafka command
envelope we already use for `email` and `linkedin_invite`.

### Gained

  - ~2,500 fewer lines of Python
  - Zero mode switches; one path
  - New integrations = one file
  - Repo readable cover-to-cover in an afternoon
  - No more "which dispatcher fires this" debugging

## Rollback

Master is untouched until v2 reaches parity. If v2 deploys break or
parity is not reachable, abandon the branch. No production impact.

After v2 master-reset, rollback means redeploying the pre-reset SHA.
Tag the master tip before reset as `pre-v2-nuke` for the rollback path.

## Operational rules going forward

  - Every architectural decision lands as an ADR in
    `omni-vault/wiki/architecture/`
  - Every production incident lands as a postmortem in
    `omni-vault/wiki/postmortems/`

    pushes unless the webhook itself is being repaired


## Addendum (2026-05-26) — Redpanda as the event log of record

Migration 021 put the durable event log in a Postgres ``events`` table.
That was a regression from the SOTA stack we already run. **Migration 022
corrects this**: Redpanda is the source of truth, Postgres holds
projections only.

### What changed

- ``events`` Postgres table — **dropped**
- ``_v`` projection views — **dropped**
- ``contacts`` / ``companies`` / ``deals`` / ``leads`` / ``messages`` —
  **created** as real projection tables (RLS-protected, upserted by a
  consumer worker)
- ``events_archive`` — **created** as a queryable historical side index
  with ``UNIQUE (kafka_topic, kafka_partition, kafka_offset)`` for
  idempotency
- ``projector_offsets`` — **created** for restart-safe consumer resume
- ``app/services/bus.py`` — aiokafka producer wrapper; every node and
  every router publishes events through this single module
- ``app/projector/main.py`` — long-running consumer that drives the
  projector tables + archive
- ``app/routers/events.py`` — POST publishes to ``omni.events`` (returns
  202, not 201, because durable archival is asynchronous); GET reads
  from ``events_archive``
- ``app/routers/projections.py`` — reads the new projection tables (no
  view trickery)
- ``app/routers/inbox.py`` — reads the new ``messages`` table directly
- ``app/routers/nodes.py`` — the ``/execute`` endpoint now publishes any
  events the node returns (nodes themselves stay pure / testable)
- ``docker-compose.yml`` — adds the ``projector`` service; removes the
  legacy ``sync-worker`` and ``transition-worker`` (their modules were
  deleted in the nuke commit) and the ``CHANNEL_MUSCLE_MODE`` env var

### Why this is the SOTA shape

- **Redpanda + Flink + Postgres-projections** is the textbook
  event-sourcing architecture. Every serious multi-tenant SaaS that has
  to replay history converges on this shape.
- **Tenant isolation still enforced by RLS** — the projection tables are
  RLS-protected. The bus carries ``workspace_id`` as the partition key.
- **Replay is real**: rewind the consumer group offset to 0, the
  projector rebuilds every projection table from the topic. Operators
  never need to write replay code.
- **Volatile vs durable**: ``omni.events`` is durable (tiered storage
  when it grows). ``outreach.commands`` / ``outreach.results`` /
  ``outreach.transitions`` are in-flight only, short retention.
- **Operability**: one consumer worker, idempotent via
  ``(topic, partition, offset)`` unique constraint. Restart-safe.

### Rollback

Migration 022 ``downgrade()`` drops the projection tables. To restore
021's Postgres-events shape, downgrade past 022 and reapply 021. The
``omni.events`` topic retains the data either way — replay rebuilds.
